# Build notes: 0.23.0 (cut 2026-10-31, never published)

These are the detailed per-merge entries behind the `[0.23.5]` section of
[`CHANGELOG.md`](../../CHANGELOG.md). 0.23.0 was cut but never tagged or published;
its content ships in 0.23.5. You do not need this file to upgrade: the summary and
the upgrade digest in `[0.23.5]` are self-contained.


Counted from 0.22.43 (2026-10-25), the intermediate
`0.22.44`–`0.22.58` versions were per-merge build numbers on `develop` that
were never tagged or published; this section covers the whole span. This is a MINOR release
because it adds public surface: a second top-level package with its own
console script, a new `athenaeum receipts` command group, and three new
optional extras. Nothing was removed. Detailed entries follow the summary,
grouped by merge, so `## Added` / `## Changed` / `## Fixed` repeat; changes
that only affect this project's own CI and contributor tooling are collected
at the end under `## Internal`.

**Upgrading from 0.22.43:** see the upgrade notes at the top of `[0.23.5]` in the changelog.

**Highlights**

- **promptwitness (new package).** A harness-agnostic, hash-chained ledger
  that records that a human typed each prompt, without storing any prompt
  text. It ships a chain verifier, optional Ed25519 signing (file or OS
  keystore keys), optional external anchoring (OpenTimestamps, and RFC 3161
  when you configure a timestamp authority), a Claude Code hook adapter, and
  `promptwitness verify` / `promptwitness demo` for checking a transcript
  against the ledger turn by turn.
- **Receipt sealing and witness attestation.** Transcript receipts can be
  signed with a key held outside the nightly process, verified with only the
  public key, and anchored nightly, with anchor records mirrored into the
  knowledge repo so that a deleted ledger is still detectable. Intake can
  attest `user-stated` memories against the witness ledger, and
  witness-corroborated claims rank in source-precedence tier 1 alongside
  `user:` (no existing rank moved). `athenaeum receipts attest-readout`
  reports witnessed hits and every provenance miss.
- **Contact-record fold and repair.** Merges no longer leave an absorbed
  person's contact record behind, and `athenaeum repair --contact-records`
  cleans up records that earlier merges, or duplicate copies of the same
  record, left claiming one uid. `recall <email>` is much faster on large
  stores, because it no longer rebuilds the whole entity index for a
  single-address lookup. Every contact-record writer now runs an
  attribution check before writing, logging its verdict and refusing only
  clearly non-personal values. Deeper checks, a calibration eval and model
  escalation ship in observe (shadow) mode, and compiled pages no longer
  pick up contact tokens that a note merely mentions.
- **CI and evaluation gate rework (contributors only).** The eval-receipt
  gate now judges a pull request by the base branch's copy of its own rules,
  identifies the LLM surface by symbol rather than by file, and accepts a
  receipt across rebases when nothing an eval reads has changed. A new
  `clean-venv` CI job installs the documented `pip install -e ".[dev]"` path
  without the lock file. None of this changes the installed package.

### Changed

- **Faster lookups on large stores (issues athenaeum#2180, athenaeum#2181,
  athenaeum#2178, athenaeum#2243).** The librarian's email-named-candidate
  gate reuses the run's entity index instead of rebuilding it for every
  candidate. `read_entity` / `person_read` (MCP), `pii.read_entity` and
  `pii.read_identifier_facts` locate a single uid's page through the
  filename fast path and the persisted entity-index cache. Callers that need
  only a few frontmatter keys can opt in to a field-selective parse
  (`models.parse_frontmatter_selective`). `json_utils.extract_json_object`
  gives up after 128 failed anchors, so a pathological model reply full of
  unmatched `{` costs well under a second instead of tens of seconds; an
  object sitting behind more than 128 stray braces is no longer found.
  Answers are otherwise unchanged.

- **North star: filing is verification, tiers are measured, schema is data
  (`docs/north-star.md`, amended 2026-10-30).** New §2.12 makes the librarian
  responsible for what it files: every value is checked against the store and
  its cited source before it is absorbed, a failed check is escalated to
  reasoning that files the value where it truly belongs (never just refused),
  and the rule binds internal writers such as migrations, repairs, folds and
  compiles. §2.2 now chooses the reasoning tier for each question class by
  measured eval accuracy rather than by escalating up a price ladder, with a
  human asked only below a calibrated confidence threshold. §2.7 extends
  "rules are data" to schema: data that does not fit the configured page
  types produces a schema-amendment proposal for a human to adopt. Docs only;
  no behaviour changes in this release.

### Added

- **Contact-value attribution check, in observe mode, at every contact-record
  writer (issue athenaeum#2210).** A new seam,
  `pii.check_contact_attribution` (implemented in `athenaeum.pii_attribution`),
  runs four deterministic checks before a value is written: D1 non-personal,
  D2 held elsewhere, D3 not a person and D4 fan-out. The observed-contact,
  correction-add, PII-migration and contact-fold writers all call it,
  including the fold that `dedupe persons --apply` runs. Each verdict is
  logged to an attribution log on the excluded contacts surface (the log row
  never carries the value itself), and suspects are parked in an idempotent
  suspect store. The writers otherwise behave as before, with one exception:
  the narrow non-personal shapes (relay local-part prefixes, the owner's own
  addresses on another page, configured mailer domains) are enforced and not
  written. Nothing is checked under `--dry-run`, and no model is called. New
  configuration: `librarian.attribution.relay_local_prefixes`,
  `librarian.attribution.relay_domains` and
  `librarian.attribution.operator_mailer_domains`.

- **Persisted, HMAC-keyed `ExcludedRecordIndex` cache, in the erasure
  cascade's delete set (issue athenaeum#2182).** athenaeum#2179 deliberately
  left `pii.ExcludedRecordIndex` in-memory-only: "a cache of it would be a
  copy of excluded PII that the erasure cascade does not reach." The new
  `athenaeum.contact_index_cache` module persists it anyway, by changing
  what hits disk — only the HMAC-SHA256 digest of each address (keyed under
  the same per-corpus `_erasure_hmac_key` `athenaeum.erasure` already
  mints/purges) plus each record's opaque uid, never a raw address.
  Invalidation copies `athenaeum.entity_index_cache`'s discipline exactly:
  every record `stat`-ed on every load, only changed records re-parsed,
  atomic 0600-inside-0700 writes, a corrupt/wrong-version/wrong-root/
  wrong-key-fingerprint cache rebuilt wholesale. `erase_contact_record`
  deletes a record file and drops its cache entry in one call, and — handed
  the caller's live index — unregisters it from memory too, so an erased
  address is unresolvable immediately, with no reload (the new
  `ExcludedRecordIndex.unregister`, the counterpart to `register`).
  `identity_resolution.resolve_handle_query`'s email-handle branch uses the
  cache when `cache_dir` is given, exactly as it already does for
  `entity_index_cache`; the librarian's compile-time caller is untouched.
  See `docs/design/contact-index-writer-coherence.md` for why
  `pii.mark_bounced`'s existing one-shot-load-plus-`register` discipline
  stays correct underneath a persisted initial load, and
  `scripts/bench_contact_index_cache.py` for the before/after timing
  methodology against a synthetic ~13k-record fixture corpus.

- **`correct-notes` can drop a whole `##` section (issue athenaeum#2236).**
  A third record kind in the same `correct-notes` batch, validation and
  ledger machinery the bullet `move` / `drop` records use: address a heading
  by a stable `section_id` with `action: drop`. The id is a slug of the
  heading text plus a 1-based ordinal counting earlier `##` headings with
  that exact text (the second `## Notes` on a page is `notes-2`), computed by
  `athenaeum.note_corrections.section_id`. Two different headings that
  slugify to the same id are treated as ambiguous and refused like an
  unknown id. Trailing footnotes are not counted as part of a section's span.

- **Attribution verification, continued: context checks, a calibration
  eval, shadow-mode escalation and placement, and contact-token scrubbing in
  compiled pages (issues athenaeum#2215, athenaeum#2211, athenaeum#2212,
  athenaeum#2216).**
  - **Context checks C1-C3** add evidence to the attribution verdict: the
    value appears inline on another person's page (C1), the local part names
    someone else (C2), or the cited source does not support the attribution
    (C3). They change no writer's output. New knobs:
    `librarian.attribution.context_labels` and
    `librarian.attribution.context_window_chars`.
  - **A calibration eval** (`tests/evals/test_attribution_eval.py`, opt-in
    and deselected by default) with a generated 420-case dataset, plus the
    shipped calibration record `calibration_data/contact_attribution.yaml`.
    Every question class ships unmeasured (`passes: false`), so every class
    stays in observe mode.
  - **Escalation and placement, in shadow mode.** With
    `librarian.attribution.escalate: true` (default `false`, capped by
    `librarian.attribution.max_escalations_per_run`, default 25), suspects
    are sent to the model tier chosen for their question class. The proposed
    placement (re-attribution, alias, merge proposal, confirmation, or the
    human queue) is logged, and nothing is filed. A model-placed value is
    always recorded as `unclassified` and never grants outreach eligibility.
    New `athenaeum attribution show | place` commands read one parked
    suspect and file a human answer for it.
  - **Tier-3 compiled output no longer carries contact tokens.** Email
    addresses and phone numbers that a source note only mentions are removed
    from the page body the compile writes, on both the batch and synchronous
    paths, and parked for attribution. Values in name fields are kept, and
    addresses already in an existing page body are not touched.

- **`witnessed` joins source-precedence tier 1, and the rewrite is persisted
  onto the memory (issue athenaeum#2159).** A `witnessed` receipt
  (athenaeum#2158) changed nothing the resolver saw: precedence keys on the
  memory's `source:` SCALAR, so a witness-corroborated claim still compared
  as `claude:inferred`. Tier 1 now carries two tokens —
  `user:<conversation-ref> / witnessed:<session-ref>` — in the same "two
  tokens, one rank" form tier 2 (`linkedin:` / `twitter:`) already used, and
  both intake and `repair --backfill-sources` write the ranked token back.
  - **No rank moved.** Operator ruling 9 (2026-10-28, epic athenaeum#2144)
    declined a tier ABOVE `user:`: a harness witness corroborates the user's
    own word, it does not outrank it. Still 9 tiers,
    `precedence.UNKNOWN_SOURCE_RANK` still 9, and every pre-existing token's
    rank is pinned against a frozen snapshot rather than re-derived from the
    live taxonomy (which would make the "nothing shifted" check vacuous).
  - **A design-lock change, so every taxonomy site moved together:** the
    canonical `resolutions._RESOLVE_SYSTEM` prose, `precedence.
    SOURCE_PRECEDENCE_TIERS`, the regenerated golden + `docs/design/
    prompts.md`, `conflict-resolution.md` §11, `provenance-shape.md` §10.1,
    `contradiction-detection.md` §3 (which publishes its own copy), and
    `field-corrections.md` §6.1's inline denominator, which had to go 10 → 11
    tokens or its own positive control would stop firing.
  - **One owner for the rewrite, so the two writers cannot drift.**
    `repair`'s `_yaml_scalar_literal` / `_set_frontmatter_scalar` moved
    verbatim down to a new L1 leaf, `athenaeum.frontmatter_edit` (`repair` is
    L4, `intake` is L2), which also owns `witnessed_source_fields` — the only
    place the four `witnessed` fields are composed and the only place the
    `#turn<N>` ref is built. `transcript_receipts.attest_user_stated_records`
    is likewise now shared, so intake and `repair` cannot disagree about
    which claims are witnessed.
  - **The subtle one: `#turn<N>` is the MEMORY's `originTurn`**, resolved
    through `transcript_verify._best_effort_ref` — the same numbering
    `repair`'s `user:<ref>` already used. The witness ledger's own
    per-session `turn` counter is a DIFFERENT numbering and reaches the file
    only as `witness_ref`'s `seq` segment. Pinned by a fixture where all
    three numbers differ.
  - **Eligibility is deliberately narrow.** Only a DEFAULTED
    `claude:inferred` source or an existing `user:` source is rewritten; a
    caller-declared, non-default, non-`user:` source is never
    second-guessed, and an absent `source` key is not a claim this pass gets
    to attribute. `repair`'s candidate selection is unchanged (still the
    exactly-defaulted scalar only).
  - Both writers are gated by `librarian.witness_attestation_enabled`
    (default off), and the flag-off path is pinned byte- AND
    mtime-identical. The intake write requires an already-acquired
    `RunLock`, checked before any no-op condition, mirroring
    `persist_recovered_origin_session_id` (athenaeum#2038).

- **Design: attribution verification for contact values
  (`docs/design/attribution-verification.md`, epic athenaeum#2192).** Specifies
  one verification seam that every contact-value writer calls, the librarian's
  own migrations, folds and compiles included; an ordered deterministic check
  catalogue; escalation of suspects to the model tier evals measure for each
  question class, with re-attribution to the real owner, structured aliases and
  same-entity merge proposals; a human queue only below calibrated confidence;
  observe mode before enforce; and the calibration eval that sets tiers and
  thresholds. The design document itself changes no behaviour; its first
  slice, the observe-mode attribution check, is listed above (athenaeum#2210).

- **A merge now folds the absorbed uid's contact record, and `athenaeum
  repair --contact-records` cleans up the ones earlier merges left (issue
  athenaeum#2184).** When `dedupe persons --apply` or a `fold-into-existing`
  approve absorbed a person page, the absorbed uid's record on the excluded
  contacts surface stayed behind. Every address on it then resolved to two
  uids, and no sanctioned path could reach it. Both merge paths now fold that
  record onto the canonical uid's record. Addresses the canonical record lacks
  are added across `emails`, `alt_emails`, `former_emails` and `phones`, with
  per-value `field_sources` provenance, and per-address bounce closes and
  classifications move with them. Addresses it already lists are dropped. The
  absorbed record is then retired: renamed to `<name>.md.retired`, stamped
  `folded_into`, and logged to `_contact_record_retirements.jsonl`. It is never
  deleted. The new repair mode finds records whose uid was absorbed by an
  earlier merge (through a tombstone's `folded_into`, a canonical page's
  `merged_from`, or `_merge_provenance.jsonl`) and folds them the same way. It
  also retires a slug-only duplicate copy of a uid's record when every value
  on that copy is already on the `<uid>`-named copy. Divergent copies,
  ambiguous canonicals and page-less uids with no merge record are reported
  and never touched. It is dry-run by default, prints counts only, and takes
  the run lock on `--apply`. Nothing rebuilds the recall index, because the
  excluded surface is not in it. A deployment that has not mapped `pii` to an
  excluded surface is a no-op.

- **`athenaeum receipts attest-readout`: witnessed hits, and every provenance
  miss as an INCIDENT (issue athenaeum#2160).** Reads the receipt ledger and
  the witness index — and nothing else, no transcript — and reports the
  `user-stated` total, the `witnessed` total split by `witness_tag`
  (`typed` / `slash-args`), misses broken down by reason, the unsigned-line
  count and anchor coverage, the `witness_hook_errors.jsonl` count by error
  class, and the `session-close` deficit (`turns - turns_witnessed`). Exits
  `5` when any incident exists, `0` when none does. `--since YYYY-MM` narrows
  the window; `--json` emits the same object the text rendering is built
  from, so the two cannot disagree about a number.
  - **A miss is an incident, not a rate.** Operator ruling 10 (2026-10-28)
    settled this: the miss counter stays, but every miss other than
    `flag-off` is surfaced individually with its reason, session and
    `witness_ref`, and there is deliberately NO tolerated miss rate and no
    readout window beyond `--since`. A miss whose receipt carries
    `transcript_origin: human` and `transcript_entrypoint: cli` is flagged a
    likely false negative — it looked human-and-interactive and still did not
    attest.
  - **No plaintext, no digests.** The output is counts, enum labels, session
    ids and `<ledger_id>:<seq>` coordinates;
    `tests/test_witness_readout.py::TestNoPlaintext` asserts no 64-hex run
    appears in either rendering, against a fixture whose receipts all carry
    real 64-hex digests.
  - **One summary, two callers.** The computation lives in
    `athenaeum.witness_readout` (L3), not in the CLI, because the nightly
    librarian calls the same `build_readout`: at the end of a run, right
    after the anchoring pass, it logs one WARNING per incident CLASS with its
    count — not one per incident, which on a bad night would be one line per
    memory. Gated on `librarian.witness_attestation_enabled` (default off),
    which is the honest flag: with attestation off every `user-stated`
    receipt carries `witness_miss: flag-off`, which ruling 10 excludes from
    the incident set, so there would be nothing to warn about. Non-fatal by
    construction — a readout never changes a run's exit code.
  - `docs/measurements/witness-attestation-readout.md` is the fill-in
    template for a recorded reading. `AttestationIndex.anchored_through()` is
    a new narrow public accessor, added so the readout reports per-ledger
    anchor coverage without reaching into a private attribute.
  - **Two things the obvious implementation gets wrong, both found in review
    and both load-bearing for ruling 10** — a readout that fires on a healthy
    night makes the incident channel noise, which defeats "misses should be
    zero absent an incident" just as surely as missing a real one. First, the
    receipt ledger is append-only, so it holds HISTORY: a memory whose miss
    was later resolved to a `witnessed` hit has both lines on disk, and the
    readout therefore collapses to the CURRENT receipt per memory
    (latest-wins, matching `lookup_receipt`'s own selection) before counting
    anything. Second, `turns - turns_witnessed` is NOT the `session-close`
    deficit: `session_close` counts `turns` as every `kind="turn"` line, which
    on a healthy session includes a `<system-reminder>`, a finished
    subagent's `<task-notification>`, a subagent prompt, and the first turn
    of a plain `claude "<prompt>"` TTY launch. The deficit is computed over
    the witness-ELIGIBLE population instead, and the close lines' own
    cumulative snapshot is reported latest-wins per session rather than
    summed (each close line re-scans the whole ledger, so summing two
    double-counts a resumed session).

- **Nightly witness anchoring, the receipt `AnchoringSealer`, and an
  off-machine mirror of anchor records (issue athenaeum#2040).** The witness
  design's last unbuilt anchoring path: at the end of a librarian run, under
  its own run lock, athenaeum now anchors every receipt partition that changed
  since its own last anchor, anchors the witness chain head, upgrades pending
  OpenTimestamps proofs, and mirrors every new anchor record into
  `wiki/_witness_anchors/<YYYY-MM>.jsonl` with its proof under `proofs/`.
  Gated by `librarian.witness_ledger_enabled` (default off); the same pass is
  available on demand as `athenaeum receipts anchor`.
  - **Why the mirror matters more than the stamp.** Every other layer the
    witness design builds — the hash chain, signatures, in-session anchors —
    lives in files the same OS user can remove, so deleting the whole ledger
    was undetectable (athenaeum#2144's attack window (b)). These records are
    pushed with the knowledge repo, so a ledger that is gone can still be
    shown to have existed, up to the last mirrored `seq`, with an attestation
    for when. They carry exactly `ledger_id`, `seq`, `line_hash` and the
    attestations — nothing prompt-derived ever reaches the pushed repo.
  - **`receipt_sealers.AnchoringSealer`** is the second real
    `transcript_receipts.Sealer`, and it landed with `transcript_receipts.py`
    unchanged, exactly as that module's `Sealer` docstring promised. It is
    never called from `append_receipt`: one network round trip per receipt is
    not a cost intake can pay, and the whole-partition digest it commits to
    would be invalidated by the very next appended line. `select_anchorers`
    is its own selection seam alongside the unchanged `select_sealer` —
    signing and anchoring answer different questions (*who sealed this* vs
    *by when did this exist*) and are independent choices.
  - **An attestation the lock-free paths already obtained is imported, not
    re-stamped.** Keyed on the digest, not the subject. A re-stamp would
    spend a calendar round trip to learn something already known and would
    record a later `claimed_time` for content demonstrably older than that,
    which is strictly worse evidence.
  - Every `wiki/` write on this path requires an already-acquired `RunLock`
    and raises `LockNotHeld` without one. Network failure is never an error:
    `local-clock` is mandatory and cannot fail, and every other adapter
    degrades to a `failed` attestation, so an offline nightly still records a
    stamp and the next pass retries — "already anchored" means every
    configured source holds a non-`failed` attestation for the current
    digest, never digest equality alone, which would have made an offline
    night's failure permanent.
  - **A quiet night writes nothing.** The chain head is anchored only when
    there is witness content past the highest head `seq` any anchor has
    committed to. Anchoring is how a line is shown to have existed by some
    time, so with nothing appended since the last head anchor there is
    nothing to bound — and because anchoring itself appends lines, an
    ungated pass would have produced an anchor line, a mirror record, a
    commit and a push every single night regardless of whether a session
    ever ran.

- **A `clean-venv` CI job, so the documented install path is actually tested
  (issue athenaeum#2136).** Every other CI job constrains its install to
  `requirements-ci.lock`. That is right for reproducibility and wrong as the
  only coverage: pyproject's PUBLISHED dependency ranges were never resolved by
  CI, so the `httpx` break below was invisible here and surfaced first to a
  release reviewer following `CONTRIBUTING.md`. The new job installs
  `pip install -e ".[dev]"` with no lock, records the resolved tree, collects
  the whole suite, and runs a smoke subset of the modules that touch the
  third-party dependency surface directly. It is wired into the `CI Required`
  aggregate, so a drift of this kind now fails a PR.
  - **`scripts/check_declared_imports.py`** names an undeclared dependency
    directly instead of letting it surface as a downstream `ImportError`: it
    fails when `src/` or `tests/` imports a third-party package
    `pyproject.toml` declares nowhere, printing the import and its file. A
    genuinely optional import guarded by `try: ... except ImportError` is
    exempt; a lazy import inside a function body is not (the ruling
    athenaeum#542 already made for `numpy`). Offline, no new dependency,
    runnable locally.
  - **The test suite's environment contract is written down** — a new
    **Test-suite environment contract** section in `CONTRIBUTING.md`, and
    `tests/env_contract.py` as its enforcement. A test whose MACHINE
    precondition is unmet now skips naming the precondition rather than
    failing. Under `ATHENAEUM_TEST_ENV_CONTRACT=strict` — which the
    `clean-venv` job sets — those skips become failures instead, so "skipped"
    cannot mask "undeclared".

- **Transcript receipts can be cryptographically sealed.** `NoopSealer` is
  still the default, so nothing changes until you opt in. Setting
  `librarian.receipt_sealer: signing` makes the intake writer sign each
  appended receipt range with an Ed25519 key that lives OUTSIDE the nightly
  process, so a forged ledger line needs the key rather than just write
  access to the knowledge repo.
  - Key placement is an adapter seam (`SigningKeyProvider` in the new
    `athenaeum.receipt_sealers`), not a hard-coded custody. The first and
    only adapter today is a 1Password service account
    (`librarian.receipt_signing.key_provider: onepassword`), which reads an
    `op://` reference through the `op` CLI and holds the key in memory for
    the signing call only — never on disk, never cached. A hardware key or a
    KMS is a later adapter behind the same three methods.
  - Signing needs the optional `signing` extra
    (`pip install 'athenaeum[signing]'`); the core install is unchanged and
    the module imports `cryptography` lazily.
  - **The nightly never needs the key.** With `signing` configured and no
    service-account token in the environment, intake appends its receipt
    lines exactly as before, logs ONE warning for the whole run, and
    produces no seal. Sealing is then a supervised step.
  - New `athenaeum receipts seal` signs every unsealed range and needs a
    reachable key; `athenaeum receipts verify` reports unsealed ranges and
    seals that no longer verify, by partition and line range only — never
    receipt content — and needs only the public key, which can be configured
    inline (`librarian.receipt_signing.public_key_openssh`) so verification
    runs unattended with no 1Password access at all.
  - An unknown `receipt_sealer` or `key_provider` value RAISES rather than
    silently falling back to not sealing.

- **A `claude:inferred` default now records which model inferred it and in
  which session** (issue athenaeum#2148), without changing the `claude:inferred`
  scalar itself: `mcp_server.remember` stamps `model`/`originSessionId`
  extras, and `intake.py` fills `AutoMemoryFile.model`/`.source_ref` in
  memory for AI-attributed auto-memory (raw stays write-once).

- **New top-level `promptwitness` package: canonical digest, hash-chained
  ledger v1, chain verifier, `promptwitness status`, and an enforced
  import boundary against `athenaeum` (issue athenaeum#2147, foundational
  slice of the prompt-witness-ledger epic, athenaeum#2144).** Standard
  library only at import time; zero `athenaeum` imports (AST-scanned).
  `promptwitness.canon.normalize` is parity-tested against
  `transcript_verify._normalize`. See `docs/design/witness-ledger.md` for
  the full design and the security boundary it does and does not prove.
  Signing (athenaeum#2150), anchoring (athenaeum#2151) and the Claude Code
  harness adapter (athenaeum#2149) are separate, blocked-on-this issues.

- **`promptwitness` signing: a `KeyProvider` protocol, the key-strength
  vocabulary, and the `none` / `software-file` adapters (issue athenaeum#2150,
  part of the prompt-witness-ledger epic, athenaeum#2144).**
  `promptwitness.signing.KeyProvider` (`key_id`/`algorithm`/`strength`/
  `presence_required`/`sign`/`public_key`) is structurally a
  `ledger.KeyProviderLike`. The `software-file` adapter is an Ed25519 PEM
  under `PROMPTWITNESS_DIR/keys/` (mode 0600, `cryptography` imported
  lazily); `promptwitness keygen` generates one. A missing key or absent
  `cryptography` degrades to an unsigned line plus one warning per process,
  never a blocked hook. `ledger.verify_chain` additively reports signed vs.
  unsigned line counts and, given public keys, per-line signature validity;
  `ledger.append_line` additively accepts `extra_signers` so a `key-rotate`
  line can carry a second signature from the old key alongside the new one.

- **`promptwitness` `os-keystore` key adapter: macOS Keychain, Linux Secret
  Service, Windows DPAPI (issue athenaeum#2152, part of the
  prompt-witness-ledger epic, athenaeum#2144).** The Ed25519 seed lives in the
  OS keystore instead of a plaintext PEM, and signing still happens in-process
  with no added per-turn friction. Select it with
  `PROMPTWITNESS_KEY_PROVIDER=os-keystore` (backend by platform, overridable
  with `PROMPTWITNESS_KEYSTORE_BACKEND`); create the key with
  `promptwitness keygen --provider os-keystore`, which refuses to replace an
  existing key without `--force`.
  - **This tier protects the key at rest and nothing else**, and the docs say
    so plainly: a stolen disk or backup yields no usable key, but the user's
    own session can read the item back without a prompt, so
    `presence_required()` is `False` and an `os-keystore` signature makes no
    claim at all about a human being present.
  - Key material travels on **stdin** (macOS `security -i`, which reads its
    commands from stdin rather than argv; `secret-tool store`) or not at all
    (DPAPI is an in-process `ctypes` call), never on argv, which is
    world-readable on every platform; a test asserts that over the real
    `subprocess` boundary. Keystore children run in their own session with no
    controlling terminal, so no keystore tool can prompt on `/dev/tty` or take
    the terminal from the session the hook is observing. The Windows protected
    blob is written atomically at mode 0600, in binary mode.
  - **A store is verified by reading it back**, and "no key here" is kept
    distinct from "I cannot tell you what is here": only a genuinely absent
    item lets `keygen` write without `--force`, so a locked keychain, a
    timeout, a missing tool or a blob belonging to another user profile all
    refuse rather than destroying a live key.
  - An unavailable keystore — tool missing, keystore locked, DPAPI refusal, no
    item stored, a malformed item — degrades to an unsigned line plus one
    warning for the whole process, exactly like the `software-file` adapter,
    and never blocks the hook.

- **The Claude Code harness adapter for the prompt witness ledger** (issue
  athenaeum#2149): `promptwitness.harness.claude_code` classifies every
  `UserPromptSubmit` prompt into a kind (`human`, `slash-command`,
  `task-notification`, `local-command`, `system`, `unknown`, `subagent`,
  `launch-argument`) and an entry channel (`interactive`, `headless`,
  `bridge`, `unknown`), extracts typed/pasted/slash-args segments, detects
  session resumption, and a new `promptwitness hook claude-code --event
  session-end` subcommand closes each session with its turn/witnessed
  counts. `athenaeum.claude_code_adapter` wires the per-turn call in,
  gated off by default behind `ATHENAEUM_WITNESS_LEDGER_ENABLED`, with a
  silent no-op guard (`<cache_dir>/witness_hook_errors.jsonl`) so a witness
  failure can never surface as hook noise or change the hook's output.
  Headless and bridge lines are never counted as human, per
  `docs/design/witness-ledger.md`'s operator rulings. Out of scope here:
  signing (athenaeum#2150) and intake lookup (athenaeum#2158).

- **`promptwitness` external anchoring: `Anchorer` protocol, the mandatory
  `LocalClockAnchorer`, and an `OpenTimestampsAnchorer` with configurable
  full Bitcoin verification (issue athenaeum#2151).** `LocalClockAnchorer`
  always runs and always produces a `complete` (but "none independent")
  attestation, even when every other adapter fails. `OpenTimestampsAnchorer`
  lazily imports `opentimestamps` (the `witness-anchor` extra), stamps
  against the default public calendars, stores proofs under
  `anchors/<subject-safe>.ots`, and upgrades a pending proof only once the
  new proof verifies. Full verification reads block headers from a
  configurable Esplora-compatible source (`--block-source` /

- **The Claude Code harness adapter records an optional `signals.launcher`
  label** (issue athenaeum#2172), read from a new `PROMPTWITNESS_LAUNCHER`
  env var: a program that starts `claude` (a scheduler, a CI runner) can tag
  its ledger lines with its own name. The value is sanitised (Unicode
  control/format characters stripped, trimmed, capped at 64 characters) and
  the `launcher` key is omitted entirely when empty, unset, or empty after
  sanitising. It is a label only — it never affects `channel`,
  `prompt_kind`, or `LedgerIndex.is_witnessable_human`, and no ledger schema

- **`promptwitness` RFC 3161 anchoring: an optional, immediate second
  attestation source alongside OpenTimestamps (issue athenaeum#2157).**
  `Rfc3161Anchorer` (`promptwitness.anchor_rfc3161`) builds a timestamp
  query with `openssl ts -query` and POSTs it to a configured TSA with
  `urllib`; the reply is stored at `anchors/<subject-safe>.tsr` and recorded
  as `rfc3161:<tsa-host>`. `verify()` runs `openssl ts -verify` against a
  configured CA bundle, recorded as `rfc3161-ca:<bundle-name>`; with no CA
  bundle configured, verification fails cleanly
  (`rfc3161-ca:unconfigured`), never an exception. The subprocess and HTTP
  calls are both injectable seams, so tests never shell out or touch the
  network. Off by default, and no TSA URL is hard-coded: the adapter is
  configured via `--rfc3161-url`/`PROMPTWITNESS_RFC3161_URL` and
  `--rfc3161-ca-bundle`/`PROMPTWITNESS_RFC3161_CA_BUNDLE` on the existing
  `promptwitness anchor` command, and is simply not offered — no `anchor`
  line, no `failed` attestation — when no URL resolves. Implemented as a
  sibling module (`anchor_rfc3161.py`), not the package submodule the issue
  named, since `anchor.py` (athenaeum#2151) shipped as a single module, not
  a package. `anchor()` validates the TSA reply before trusting it —
  empty, non-DER, or non-`granted` replies degrade to a `failed`
  attestation instead of `complete`, and the write goes through a sibling
  temp file so a bad reply never overwrites a prior good `.tsr` proof; and
  `anchor --upgrade` now finds a subject's prior RFC 3161 attestation (by
  `rfc3161:` source prefix) and calls the no-op `upgrade()` instead of
  re-anchoring, so it never overwrites the `.tsr` file an earlier ledger
  line's `proof_path` still names (PR athenaeum#2174 review findings).

- **`promptwitness verify` and `promptwitness demo`: a harness-agnostic
  verifier plus a static, shareable side-by-side demo (athenaeum#2155).**
  `promptwitness.verify.verify_transcript(transcript_records, ledger_index)`
  returns a per-turn verdict (`witnessed`, `not-witnessed(inserted)`,
  `digest-mismatch(edited)`, `machine-authored`, `headless`, `bridge`, or a
  hash-chain break at a named `seq`); `promptwitness verify --transcript
  ... --ledger ... [--json]` exits 0 iff every human turn is witnessed, else
  1. `promptwitness demo --synthetic --out demo.html` (the default) builds a
  five-turn synthetic session and renders two transcripts side by side —
  one untouched, one with a turn inserted after the fact and another
  edited — as static HTML with inline CSS, no `<script>`, and no network
  access; the footer carries the key strength, the anchor status, and the
  security-boundary table from the epic (athenaeum#2144), so the page
  cannot be read as an identity guarantee. Real-transcript mode
  (`--transcript ... --ledger ...`) renders the operator's own prompt text
  locally, writes the file at mode 0600, and warns on stderr — never
  publish it.
- **The witness chain head is anchored periodically in-session and at
  every SessionEnd (issue athenaeum#2156).** The `UserPromptSubmit` hook,
  after appending its own ledger line, spawns a fully detached
  `promptwitness anchor` process (closed stdio, `start_new_session=True`,
  never waited on) whenever the newest anchor activity is older than
  `ATHENAEUM_WITNESS_ANCHOR_INTERVAL_MINUTES` (default 15; `0` disables),
  guarded by `promptwitness.anchor_schedule` so two concurrent sessions in
  the same interval spawn at most one process. `session-end` (both modes)
  runs a lock-free anchor step, bounded to a 10 second budget, that
  anchors the chain head every time and each changed receipt partition
  digest (read-only; nothing under `wiki/` is written). Six new
  `librarian.receipt_anchor.*` config resolvers document the nightly
  anchoring path's (athenaeum#2040) own adapter/calendar/timeout surface.
- **Intake attests `user-stated` utterances against the witness ledger,
  with misses treated as incidents (issue athenaeum#2158).** New module
  `athenaeum.witness_attestation` joins a `user-stated` transcript claim to
  the `promptwitness` witness ledger by `promptId` (falling back to
  `(session, digest)`) through an eleven-condition hit rule — prompt kind,
  interactive channel, matching session, digest equality, an intact hash
  chain, and three transcript cross-fields (`origin.kind`, `promptSource`,
  `isSidechain`). A hit upgrades the receipt's channel to `witnessed`
  (schema v2, purely additive — v1 receipts still parse and are never
  rewritten); a miss stays `user-stated` with one of eleven `witness_miss`
  reasons and is logged at WARNING (never the claim text or a digest), with
  a provenance-incident variant for a miss that otherwise looks
  human-and-interactive. Off by default
  (`librarian.witness_attestation_enabled`); with it off, behavior and the
  `correct_*` gate's decision are byte-identical to before this issue.
  Nothing gates on attestation yet.
  - **Deviates from the issue's literal slash-command digest wording, by
    necessity.** The issue specifies `sha256(normalize(<command-args>
    text))`; the shipped producer (`promptwitness.harness.claude_code.
    slash_args_segment`, athenaeum#2149) hashes the RAW, un-normalized span
    instead, unlike `record_turn`'s own normalized `prompt_digest`. The
    literal formula would make the slash-args hit path unreachable for
    almost every real slash command. This module calls the producer
    function directly and compares against its digest rather than
    re-deriving a formula, so it tracks the producer if that formula ever
    changes. Flagged to the epic owner as a digest-contract defect, not
    resolved here — see `src/athenaeum/witness_attestation.py`'s "Known
    deviation" docstring note.
- **Attribution calibration over time: audit-sampling and threshold

  - **Fix (PR review, Seer finding A):** a question class whose threshold

  - **Clarified (PR review, Seer finding B — rejected the proposed

### Fixed

- **The eval-receipt check matches a receipt on content, not on the exact
  head commit.** A successful `Evals` run at commit X now satisfies PR head H
  when no file on `.github/llm-surface.txt` differs between X and H (a direct
  tree diff, so a rebased or force-pushed head counts too). Before, every
  update-branch, every merge-wrapper version bump and every rebase moved the
  head off the receipted commit and demanded a fresh paid eval dispatch, even
  when nothing an eval reads had changed. A surface file that changed since
  the run, or a receipt commit that cannot be read, still fails as stale. The
  workflow comment and `tests/evals/README.md` no longer call the check
  advisory: the merge wrapper waits on it and will not merge past a red one.

- **A field correction can now remove a list entry whose stored dates came
  from YAML.** List values were compared by `repr`, so an entry read from
  frontmatter with an unquoted date (`start_date: 2023-10-01`, which YAML
  parses to a `date`) never equalled the same entry submitted in a JSON batch,
  where the date is a string. An `op: remove` of, for example, an
  employment-history entry resolved to a silent `noop` ("value already
  absent"), and an `op: add` of an entry already present appended a duplicate.
  Value identity now normalizes `date`/`datetime` to ISO strings and compares
  dicts as canonical JSON with sorted keys, so neither YAML date parsing nor
  key order breaks equality. The key is used only for comparison and is never
  written.

- **`athenaeum repair --contact-records` now folds a divergent duplicate
  contact record instead of leaving it behind (issue athenaeum#2184
  follow-up).** When a uid was claimed by a `<uid>`-named record and a
  slug-named copy, the repair retired the copy only when it held nothing
  more. A copy holding an extra address, phone, bounce close or usage
  classification was reported and left in place, so the uid stayed claimed by
  two records. The repair now folds such a copy onto the `<uid>`-named record
  and retires it with reason `duplicate-fold`:
  - values and per-address facts on only one copy are kept;
  - a usage classification both copies hold for the same address is settled
    by the existing no-downgrade ladder (`observed` > `provider` >
    `unclassified`), with the newer `observed_at` winning between equal
    classes.

  Two cases still need a human and are reported, never touched: copies whose
  `name` differs after normalization, and copies whose validity (bounce/close)
  entries for the same address differ. New counts:
  `duplicate_divergent_to_fold`, `duplicate_divergent_values_to_add`,
  `duplicate_divergent_name_differs` and `duplicate_divergent_validity_differs`.
  `duplicate_divergent_reported` now counts only the pairs that need review.

- **`recall <email>` no longer rebuilds the whole entity index to find one
  page.** When an address resolved to exactly one person, the handle path
  built a full `EntityIndex` (parsing every wiki page's frontmatter) just to
  map that uid to its file, and scanned the contact surface twice. On a
  ~26k-page corpus that took about 8s per call. Now `recall` (CLI and MCP)
  passes its cache dir to `resolve_handle_query`, which:
  - locates the page by filename (`<uid>-*.md` / `<uid>.md`) when exactly
    one page there carries the uid in its frontmatter, reading only that
    page;
  - otherwise uses a persisted, stat-validated `EntityIndex` cache under
    `<cache_dir>/entity-index/` (new module `athenaeum.entity_index_cache`).

    changed, drops deleted pages, rebuilds on a missing or corrupt cache,
    and writes atomically with mode `0600`. It stores only uid, name, type
    and aliases;
  - scans the contact surface once per call instead of twice.

  Answers are unchanged. Callers that pass no `cache_dir`, including the
  librarian's compile-time caller in `tiers.py`, keep the full scan. The
  remaining frontmatter-parse cost of a full scan is tracked in

  `read_holder` (used to render `LockHeld`'s diagnostic message) could land
  in that window and see nothing, degrading the message to a bare "another
  athenaeum process" with no PID/host/heartbeat age. The rewrite now never
  truncates: a payload shorter than what's on disk is padded with trailing
  blank lines (inert to `read_holder`'s parser) up to the current size
  before a single `os.write`, and a longer payload simply extends the file
  as part of that same write — so the file size never decreases and a
  reader always sees either the complete old payload or the complete new
  one, never a mix of the two. The lockfile format, flock semantics and
  `_heartbeat_write_lock` behaviour are unchanged.

- **Eighteen tests no longer read the caller's environment instead of their
  own (issue athenaeum#2256).** Each was reproducible by running the real
  suite in an ordinary shell rather than `env -i`:
  - `test_deploy_guard.py`'s `_source_and_eval`/`_run` helpers now scrub
    `ATHENAEUM_GUARD_PYTHON` before applying each test's own `env_extra`
    (already done in `_source_and_eval_rc`, but missing from the other two),
    so a caller who exports it no longer overrides the shimmed `PATH` the
    install-cmd/`_dg_resolve_python` tests build.
  - `test_retention_policy.py` gains an autouse `_hermetic_git_config`
    fixture that sets `GIT_CONFIG_GLOBAL=/dev/null` and
    `GIT_CONFIG_NOSYSTEM=1` and strips the `GIT_CONFIG_COUNT`/`_KEY_`/`_VALUE_`
    family for every test in the module, so a caller's real global
    `core.excludesfile` naming `logs/` no longer hides the files the
    fixture's and the SUT's own git commits stage.
  - `test_receipt_sealers.py`'s subprocess-env-suppression test now
    `monkeypatch.delenv`s `OP_LOAD_DESKTOP_APP_SETTINGS`/
    `OP_BIOMETRIC_UNLOCK_ENABLED` first, so its final "didn't leak into this
    process" assertion is actually testing the provider rather than echoing
    whatever the caller's shell happened to export.
  - `test_spend.py`'s budget-window-omitted test now passes `--path` at a
    guaranteed-absent `tmp_path` directory, so `cmd_spend` never loads a
    real `~/knowledge/athenaeum.yaml` spend budget off the caller's `HOME`.
  - `test_eval_corpus_leakage.py`'s proper-noun denylist (`_real_proper_nouns`)
    now excludes names with a trailing bare number ("gate 1", "phase 2") as
    generic numbered labels rather than real identities — the exact shape
    that flagged the unrelated phrase "Gate 1" in
    `probe_subject_scope_containment.py`'s own prose. A genuine multi-word
    capitalised name with no trailing number is still caught (counter-example
    test alongside the fix).

  All five files were confirmed to fail under the leaking condition
  (`ATHENAEUM_GUARD_PYTHON`/`OP_LOAD_DESKTOP_APP_SETTINGS` exported, a global
  gitignore naming `logs/`, a spend budget configured under `HOME`, a local
  knowledge tree present) before the fix and pass both under that condition
  and under `env -i` after it. Isolation lives entirely in test fixtures; no
  CI configuration changed.

- **16 tests no longer fail on a stock macOS checkout (issue athenaeum#2255).**
  All five causes were test-side assumptions that happened to hold on the
  Linux CI runner: tests rewriting a `promptwitness` ledger partition without
  first clearing the append-only flag `ledger._apply_append_only_protection`
  applies (now cleared via `cli._clear_append_only_best_effort`, with a
  counter-example test gated on a new `append_only_protection_enforced`
  environment-contract property); a decay-bucket test fixture deriving its
  scope name directly from `tmp_path`, which collided with the default
  ephemeral-scope globs on macOS's `/private/var/folders/...` layout (now
  hashed); an `AF_UNIX` socket placed under `tmp_path`, which macOS's default
  `TMPDIR` can push past the 104-byte `sun_path` limit (now a short
  `/tmp`-rooted scratch dir); a timezone test that assumed the host runs UTC
  (now compares against the host's real `/etc/localtime` resolution); and a
  macOS-only stdlib version-probe open that an import-I/O tracker test did
  not tolerate (now tolerated by exact path, with a positive control proving
  the tracker still catches an unrelated unexpected open). No product
  behavior changed; `_system_local_timezone`'s docstring now also records,
  rather than changes, its existing `$TZ` precedence.

- **Two `test_repair.py` bounce-fold tests no longer depend on the host's
  live deployment state (issue athenaeum#2183).** `--bounce-fold --apply`
  took the run lock at `--knowledge-root`, or, if omitted, at
  `DEFAULT_KNOWLEDGE_ROOT` — the operator's real `~/knowledge`. Both tests
  omitted `--knowledge-root`, so a real librarian run holding that lock made
  them fail with exit 75, a result that depended on what else happened to
  be running on the machine. Both now pass an explicit tmp
  `--knowledge-root`, and a new regression test reproduces the exact
  failure mode — a run lock held at the root the default resolves to —
  entirely against tmp stand-ins. A new session-wide, autouse test guard
  (`tests/fixtures/default_root_guard.py`) fails any test that opens a path
  under the real default knowledge root or default cache dir, covering both
  `DEFAULT_KNOWLEDGE_ROOT` definitions (`config.py`'s call-time
  `.expanduser()` and `librarian.py`'s copy, frozen at import time).

- **Receipt signing accepts the v2 PKCS8 PEM that `op read` returns (issue
  athenaeum#2142).** With the shipped defaults, `receipt_sealer: signing`
  failed on the first `athenaeum receipts seal` with an "extra data" parse
  error, because the 1Password SSH Key `private key` field is an RFC 5958 v2
  `OneAsymmetricKey` (private key plus the optional public key) and
  `cryptography` rejects that encoding. The key loader now falls back, only
  after the ordinary parse has failed, to reading the 32-byte Ed25519 seed out
  of the v2 structure; anything that is not an Ed25519 v2 key still surfaces
  `cryptography`'s own error.
- **The SessionStart hook's vector-index freshness check works on Linux
  (athenaeum#2207).** It called BSD-only `stat -f %m`, which GNU coreutils
  reads as `--file-system`, so the comparison never produced a number and the
  hook rebuilt the vector index on every start. It now probes for GNU
  `stat -c %Y` and falls back to the BSD form.
- **Removing a page no longer leaves its contact records live (issue
  athenaeum#2217).** Page removal through `retire-pages`, the decay sweep or
  the oversize-log demotion left the removed uid's record on the contacts
  surface with nothing pointing at it, inflating the shared-address count and
  making the observed-value ownership guard decline correct writes. Each path
  now folds the record into a successor when one exists, or retires it (renamed
  out of every read and logged, never deleted) when none does, and never fails
  the removal it follows. `athenaeum repair --contact-records` also reports
  `pageless_records` and, with `--retire-pageless`, retires them. Dry run stays
  the default and output is counts and uids, never values.
- **The contact-record fold no longer carries per-address entries for
  addresses a record does not list (issue athenaeum#2196).** A stale usage
  class could land on a record with no address to attach to and, as an
  `observed` mark, read as outreach-eligible once the address was later
  written. `correct-notes` removal of an address field now drops that
  identifier's classification and validity entries too; the fold drops entries
  whose identifier is not in the merged record; the classification readers
  ignore orphans; and `repair --contact-records` counts `orphan_fact_entries`
  and prunes them under `--apply`. Bounce marks are deliberately still read
  unfiltered, since hiding one could cause a send to a dead address.
- **The correspondent shortcut no longer files the sender's address on the
  wrong person (issue athenaeum#2209).** For an introduction email the one page
  a compile created was the introducee's, so the introducer's address was
  recorded on them as `observed`. The shortcut now first resolves the address
  to an existing page (if one exists, nothing is recorded and nothing is
  escalated), then requires the created page to match the sender's name even
  when only one page was created, and with no name requires the address's local
  part to match the page's full name, `flast`, `first.last` or `firstlast`.
  Every escalation it raises now shows the address masked (`a***@example.org`)
  in both its description and its title, so a raw address no longer lands in
  `_pending_questions.md`.

### Internal

- **`docs/design/eval-trigger-surface.md` matches the current eval-gate
  rules (issue athenaeum#2237).** Docs only.

- **The eval-receipt gate is judged by the BASE commit's copy of itself
  (issue athenaeum#2227).** `.github/workflows/eval-receipt-check.yml` ran
  `python scripts/check_llm_surface_receipt.py` out of the `pull_request`
  checkout, so a PR's own copy of the script decided that PR — and since the
  merge wrapper treats any failed check as blocking, a one-line edit to the
  script in the same PR would have bypassed it. The script, and every
  repo-local file it imports, is now materialised from
  `pull_request.base.sha` with `git show` into `$RUNNER_TEMP` and run from
  there; the merge base's copy of the surface list is passed alongside the
  head's, so the union rule still applies. A base commit that predates the
  script falls back to the head copy with a `::warning::`.
  `tests/test_eval_receipt_gate_from_base.py` extracts the workflow's own
  shell bodies and runs them against throwaway repos — including the case
  that matters, a PR that weakens the gate and is failed by the base version
  anyway — so the recipe is tested rather than described. `ci.yml` is
  untouched and nothing new is installed.

- **The eval gate's `not needed` escape is structured and checked (issue
  athenaeum#2226).** The free-text form no longer passes when the reasoning
  surface changed; the replacement is
  `Evals: not needed — <category>: <symbol>[, <symbol>...]` with a category
  from a closed vocabulary (`rename-only`, `log-or-error-text`, `dead-code`,
  `refactor-equivalent`, `gate-plumbing`). The named symbol set must EQUAL the
  set the gate found changed — the failure prints both sets and the
  difference. That is all the gate checks (operator ruling 2026-10-30:
  symbol-match only). All five categories are reviewer-checked: the gate
  publishes each changed symbol's docstring-stripped `ast.unparse` before and
  after to `$GITHUB_STEP_SUMMARY`, so a reviewer reads function bodies rather
  than files. Machine re-hash checks for `rename-only` and
  `log-or-error-text` are deferred until misuse is observed. When nothing designated changed, no line is required at all.
  Vocabulary documented in `tests/evals/README.md`.

- **An eval receipt now survives a `develop` merge or a rebase (issue
  athenaeum#2225).** `receipt_covers_head` keeps its name, its call site and
  its `(covered, stale)` shape, and gains the symbol-fingerprint COVERS rule:
  a passing run at commit X satisfies head H when, for every designated
  symbol, either X and H agree structurally, or the PR changed that symbol at
  neither point — in which case the difference arrived from `develop`, where
  it was evaluated under its own PR. athenaeum#2206 compared the two trees on
  surface paths, so a rebase that brought in another PR's `tiers.py` change
  invalidated a perfectly good receipt and cost a re-dispatch. Fails closed:
  an unreadable receipt commit (fetched by sha first) or an unresolvable merge
  base is not covered, and the failure text now names the symbols that made
  the receipt stale rather than the files. `pyproject.toml` is still not
  designated, so the merge wrapper's version bump is still covered.

- **The LLM surface is designated by SYMBOL, and the designation is derived
  rather than transcribed (issue athenaeum#2224).** `.github/llm-surface.txt`
  moves from whole-file entries to `path::symbol` ones: `config.py` (8k
  lines), `librarian.py` (12k), `tiers.py` (9k), `models.py` and `search.py`
  are no longer listed whole, so an edit to an undesignated function in one of
  them no longer demands a paid eval dispatch. `tests/test_llm_surface.py`
  gains five derivations, each a membership check with a counter-example test:
  **D1** every function or method that calls the Anthropic SDK directly,
  **D2** every `PROMPT_META` row as `path::CONSTANT`, **D3** the model-routing
  seam by AST name pattern, **D4** every `LLMBackend` importer (loosened to
  "at least one entry of any form"), and **D5** no entry naming a symbol that
  no longer resolves. D1 closes the gap the old substring oracle had:
  `paste_cleanup.py` and `memory_class_backfill.py` call
  `client.messages.create` without naming `LLMBackend`, so neither was on the
  surface at all. `docs/design/prompts.md` is dropped (generated, and
  byte-pinned by `tests/test_prompt_goldens.py`). Measured by replaying the
  predicate over every PR merged to `develop` in the 30 days to 2026-10-30
  (`scripts/replay_fire_over_merged_prs.py`,
  `docs/measurements/eval-fire-replay-2026-10-30.md`): of the 68 PRs that
  tripped the old gate, 34 would not trip the new one at all.

- **"Dispatch once, at the final reviewed head" is now written down, and the
  eval gate says it (issue athenaeum#2228).** `tests/evals/README.md` gains
  the canonical statement of the rule — dispatch only when review is
  complete, the gate reports a changed reasoning surface, and no passing run
  already covers the head; never for a `develop` merge, a rebase, or a head
  that already has a run. There is no automatic retry: a red run is a finding
  to investigate (operator ruling 2026-10-30; small-sample flakiness is fixed
  at source by athenaeum#2231). The gate's own
  failure text carries a one-sentence version, because that is what a
  dispatching agent reads at decision time: it no longer says "the dispatch
  is stale, re-run it", which was the most likely driver of the measured
  churn (19 of 23 paid runs in 30 days went to three PR branches, five of
  them following a `Merge develop` with no surface delta at all). The
  README's receipt section keeps athenaeum#2206's content-based coverage and
  reconciles its "re-dispatch after the last surface change" wording with the
  new rule.

- **The eval-receipt gate decides on structure, not on touched paths (issue
  athenaeum#2223).** `.github/llm-surface.txt` gains a `path::symbol` form —
  a top-level `def`/`class`, a `Class.method`, or a module-level constant —
  and `scripts/check_llm_surface_receipt.py` now asks whether a designated
  symbol's docstring-stripped AST differs between the merge base and the
  head (`fire`), instead of whether its file appears in the changed-path
  list. A comment, a docstring or a reformat inside a designated function no
  longer demands a paid eval dispatch; a one-literal change inside one still
  does, and an edit to an undesignated function in the same file does not.
  The decision uses the UNION of the designations at both ends, so a PR
  cannot delete its own entry to hide a change, and missing, renamed or
  unparseable symbols count as changed (fail closed). The whole-file and
  `dir/` prefix forms keep their exact meaning, so the list itself is
  unchanged by this release and a rollback to whole-file entries needs no
  code change. Stdlib only — no install is added to the gate's workflow.

- **PR CI is parallel and sharded (athenaeum#2230, athenaeum#2241).** The test
  job runs under `pytest-xdist` with `--dist loadfile` and a pip cache, then is
  split across two runner shards by a deterministic, weight-balanced partition
  (`--ci-shard INDEX/TOTAL`). A new `Coverage (combined shards)` job verifies
  that every shard reported and that every collected test ran in exactly one
  shard, then combines coverage and enforces the 75% floor. `CI Required` and
  `publish_attestation` depend on it. A plain local `pytest` is unchanged and
  stays serial. PR CI fell from 20 to 32 minutes to roughly 8 to 10.
- **A token-free nightly test tier (athenaeum#2242).** A new `nightly` marker,
  deselected by default, and `nightly.yml` (daily, and on dispatch, with no
  model credential) now carry the printed measurement tables, the 48-probe
  hook-equivalence sweep and the historical overflow-breadcrumb module. The
  default suite keeps a one-assertion replacement for each, including a
  three-probe launcher-versus-adapter byte smoke test.
- **`docs/design/attribution-verification.md` records the operator decisions
  and matches the corrected child issues (athenaeum#2221, athenaeum#2253,
  issues athenaeum#2192, athenaeum#2234).** Docs only: `auto` enforcement
