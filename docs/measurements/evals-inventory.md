# Evals inventory (issue athenaeum#552)

Operator decision (hard constraint, do not relitigate): the project is
deliberately **eval-light**. Live-API evals under `tests/evals/` stay
deselected by default (`-m 'not eval'`), run only via `evals.yml`
(workflow_dispatch / push:main), and are never a required per-PR check.
This document inventories which `src/athenaeum/` modules *warrant* a basic
eval under that philosophy, so the answer to "should X get one" is written
down once instead of re-litigated per module.

**Criterion for "warrants an eval":** the module's correctness depends on
the LLM's **output shape** in a way that can silently drift (a live model
starts emitting a structurally-different-but-plausible response the
hand-rolled parser doesn't expect), **or** on a **scoring/threshold
judgment** (does the model's classification/verdict land in the right
bucket often enough) that a unit test with a stubbed, fixed response
cannot pin — because a stub only proves the parser is well-behaved *for a
canned reply*, not that the live model still tends to produce a reply the
parser and the downstream policy can act on correctly.

Modules that call the Anthropic API but are already fully exercised by an
existing eval, or that are deterministic and merely *consume* an LLM's
prior output, are marked accordingly rather than re-covered.

## New evals added

Two new eval layers, mirroring the existing detector/resolver/recall structure exactly (synthetic "Thornhollow Advisory" cases, per-case tests that never fail individually, one aggregate-floor test, `@pytest.mark.eval`):

1. **`classify` layer** (`tests/evals/test_classify_eval.py`, `tests/evals/data/classify/cases.yaml`) — exercises `tiers.tier2_classify`. Golden set spans the entity-extraction outcome classes: a clean single-entity extraction, a multi-entity file, a placeholder-label rejection (`"Member 1"`-style), a procedural/no-entity-worthy file (expects `[]`), and an already-matched entity that should be skipped.
2. **`merge` layer** (`tests/evals/test_merge_eval.py`, `tests/evals/data/merge/cases.yaml`) — exercises `tiers.tier3_merge`. Golden set spans: a clean anchored insert, a re-confirmation that should fold into an existing footnote (not a new bullet, per athenaeum#297 dedup policy), a factual contradiction (keep-more-reliable + note discrepancy), and a principled-tension case that must produce the `ESCALATE:` branch.

Both stay fully deselected by the existing `-m 'not eval'` addopts (no `pyproject.toml` change needed — the marker registration and addopts already exist and apply to any test carrying `pytestmark = pytest.mark.eval`). Neither is wired into `ci.yml`; `evals.yml`'s `pytest tests/evals/ -m eval` picks them up automatically because it selects by marker across the whole `tests/evals/` directory, not by an enumerated file list.

3. **`write_tier_compare` layer** (`tests/evals/tier_compare.py`, `tests/evals/test_write_tier_compare.py`, `tests/evals/data/write_tier_compare/cases.yaml`) — issue athenaeum#1139. Structurally DIFFERENT from every layer above: those each exercise ONE fixed model (the knob's resolved default); this one replays the SAME corpus once per model in `CANDIDATE_MODELS` (`claude-sonnet-5`, `claude-haiku-4-5` — Anthropic tiers only, local/OSS blocked on athenaeum#1101/WONT), passing `config={"models": {"write": <model>}}` into `tiers.tier3_create`/`tiers.tier3_merge` per run, so it measures whether the `write` knob (~99.2% of metered spend) needs to stay pinned to Sonnet 5. Golden set: a simple create, a multi-entity create, a merge into a small page, and a merge into a page exceeding the 16KB `page_flag_bytes` threshold — every case's untrusted text also carries an embedded prompt-injection probe, scored for leakage on every case rather than a dedicated one. Also extended: `tests/evals/harness.py` gained `LAYER_WRITE_TIER_COMPARE` in `EvalSession.emit_summary`'s known-layer tuple. A companion offline file, `tests/evals/test_write_tier_compare_stub.py` (unmarked — runs in the default suite, no credential/network needed), proves the corpus non-empty/coverage guard and the full runner/scorer pipeline against a `FakeLLMClient` stub; see that file's module docstring for why (athenaeum#551 precedent: silently-empty fixtures must fail loudly, not skip).
4. **`underdetermined` layer** (`tests/evals/test_underdetermined_eval.py`, `tests/evals/data/underdetermined/cases.yaml`) — issue athenaeum#1518. Exercises `tiers.tier3_create` (not `tier3_merge`) on sources that UNDERDETERMINE a field the entity template invites, rather than conflict over one. Golden set: a source naming a person once with no stated affiliation, authored by a different, invented organization — asserting no affiliation is invented, and specifically not that authoring org (the plausible wrong inference — the observed failure this issue is named for); a source naming a person performing one action next to an adjacent fact in the note's own first-person author's voice — asserting the adjacent fact is not folded into the named person's role; a source whose gap is material to the page's own purpose — asserting the page's existing `## Open Questions` mechanism fires (no new escalation path was added; `CREATE_SYSTEM` already asks for this section); and a negative control where the affiliation IS stated plainly — asserting it populates correctly, proving the fix is not blanket suppression. `CREATE_SYSTEM` (`src/athenaeum/tiers.py`) also gained an explicit rule for this issue: a field the source is SILENT on stays absent — silence is distinct from "nothing contradicts it" — citing `store.py:952`'s existing narrower rule ("do not invent a classification the note does not state") as precedent. That prompt edit moved exactly one golden snapshot (`tests/data/prompts/tiers.create_system.txt`); see the PR body for the sha256 diff. **The recorded-response fixtures that would let this layer replay in regular CI (`tests/fixtures/recorded/underdetermined/`) are NOT seeded** — no live model backend was reachable from the lane that built this layer (see PR body) — so it stays unlisted in `tests/fixtures/recorded/seeded-layers.yml` and its replay test in `tests/test_recorded_fixtures.py` skips cleanly with an explicit reason, exactly like every other never-seeded layer; it does not error the suite. Seeding it (an `evals.yml` `record=true` run) is a tracked follow-up.
5. **`attachment` layer** (`tests/evals/test_attachment_eval.py`, `tests/evals/attachment.py`, `tests/evals/data/attachment/cases.yaml`) — issue athenaeum#1580. Structurally different again: every layer above exercises ONE tier's output in isolation, this one runs the WHOLE chain via `athenaeum.librarian.process_one` against a materialized `tests/evals/corpus.build_corpus("core")` tree (plus three overlay pages local to the layer) and grades the **routing decision** — given a wiki that already has a page for X and a new source about X, does the source land on X's page or mint a second one? `classify/cases.yaml`'s `skip_already_matched_entity` grades whether an already-resolved entity is re-extracted, and the `merge` layer grades the SHAPE of a merge once one has been decided; neither runs against a wiki, so neither can grade attach-vs-mint. Golden set: same-name attach; name-variant attach (the live `name` / `name (qualifier)` shape, deliberately UPSTREAM of athenaeum#1577's compiled-wiki scan — a librarian that mints the variant and then has athenaeum#1577 propose folding it back has still put a second page in the wiki); a whiteboard-board export, which is a source document (`docs/north-star.md` §2.3) attaching to the entity it evidences **through the same path as any other source — no board-specific parser, per §3**; a negative control that must MINT (without it, attach-everything scores perfectly); and a two-entity source that must reach both without minting a third page for the event. Grading is structural and delta-based (`tests/evals/attachment.py`): which pages exist before and after, which changed, which `related:`/`sources:` rows appeared, whether a pending-decision surface grew. Edges carrying `role: term-overlap` are **excluded** from the attachment signal — the athenaeum#1576 compile-time relatedness writer stamps those on every newly-created page in a 96-page corpus, so a wrongly-minted duplicate reliably points at the page it should have attached to, and counting that would score the confound as a success exactly where the librarian failed worst. Per-case **tier attribution** (deterministic / CLASSIFY / WRITE-MERGE / escalation) is derived from the OBSERVED model-call sequence, never from a field in the fixture, so a pass bought with the expensive tier is visible in `eval-summary.json`. Irreversible outcomes (a merge, a demotion to source document) are graded as PROPOSALS reaching the pending queue (`docs/north-star.md` §2.8); a page that VANISHED is asserted outright rather than scored, because no aggregate floor should be able to absorb a contract violation. The grader itself is covered offline in `tests/evals/test_attachment_grading.py` (no `eval` marker — runs on every PR), since the live half is deselected by default and CI would otherwise only prove the module imports. **Fixtures are NOT seeded** — recording is a metered operator action — so `attachment` stays unlisted in `tests/fixtures/recorded/seeded-layers.yml`.
